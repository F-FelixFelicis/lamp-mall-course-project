# M4 以图搜图算法设计与实验记录

本阶段实现本地视觉检索、颜色基线、版本化索引、实时可售过滤及三端页面。查询图片不提交给外部模型服务。已运行真实图片排序与耗时实验；当前缺少两人独立相关性标注，因此尚不能给出正式 Recall@5、Precision@5 或宣称达到需求报告的相关性目标。

## 输入与输出

输入为单张 JPG、PNG 或 WebP，最大 5 MB、最短边至少 32 像素、最多 2000 万像素。服务按文件内容解码并处理方向，不信任文件扩展名。图片只在本次请求内存中用于特征提取，不创建查询图片文件，不保存查询向量。

输出为最多 5 个默认候选，接口允许 K 为 1–20，可按用户选择的灯型过滤。候选包含商品、SKU、匹配图片、当前最低有效报价和排序分数；分数不是同款概率，系统不保证识别出具体品牌或型号。若画面不含清晰灯具，用户应裁剪或重新选择照片；当前没有自动灯具检测器或经标注校准的“无匹配”阈值。

## 两种方法

主方法使用 TorchVision 的 ResNet18 ImageNet-1K V1 预训练权重，移除分类全连接层，取得平均池化后的 512 维特征并进行 L2 归一化。预处理沿用官方变换：短边缩放至 256、中心裁剪至 224、按官方均值与标准差归一化。推理采用 CPU、eval 模式和 inference_mode，不在本项目图片上训练或微调。来源见 [TorchVision 官方模型说明](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html)。

模型 SHA-256 固定为 `f37072fd47e89c5e827621c5baffa7500819f7896bbacec160b1a16c560e07ec`。API 不自动下载模型，缺少权重或依赖时返回明确的 503，文字检索继续工作。权重位于忽略目录 `.local/models`，不提交到仓库。

颜色基线将图片缩放至 128×128，转为 HSV，按 H×S×V = 8×4×4 构造 128 维联合直方图，L1 归一化后逐项开平方。它保留颜色分布，不保留空间结构，可用于观察颜色相近而灯型不同的误检。

两种方法均对单位向量使用余弦相似度，即向量内积。图库按图片提取特征，对一个 SKU 的多张图片取最大相似度，然后按分数降序排序；同分按 SKU 和文件编号确定顺序。当前使用精确矩阵检索，复杂度约为 O(Nd)，20 张图库不需要近似索引。当前构建上限为 5000 张图片，规模扩大后需另测延迟并考虑批处理与近似检索。

## 索引与业务集成

索引仅从当前可售商品图片建立，保存两个特征矩阵、图片与 SKU 关联、文件哈希、算法版本、模型哈希和索引版本。文件采用 NumPy NPZ，不允许 pickle 反序列化。构建先写临时文件，完成后原子替换；构建失败保留原索引。

返回结果前重新检查当前商品、商家、分类、SKU、有效报价、库存、图片关联与文件存在性。下架、零库存、过期报价、删除的图片关联不会因旧索引继续作为可购买候选返回。价格来自当前业务库，不使用索引中的旧价格；新增可售图片需更新索引。

管理端可查看索引状态并重新建立，商家端可图搜选品，顾客端可从相似结果进入商品详情并沿用 M3 模拟下单流程。日志只记录查询 UUID、方法、索引版本、耗时、K 和结果 SKU 编号，管理员可查看最近 20 条；无原图、文件名或查询特征。

M4 迁移 `a57f6bf4fabb` 新增 `image_search_logs`，累计 21 张业务表。当前已实现接口见 `api/openapi-m4.json`，包含 `/search/image` 及管理端索引、状态、日志接口。

## 数据集和人工判定

图库为 20 张已准备的灯具照片，查询候选为 15 张来源独立的实拍照片。冻结清单在 `assets/image_search_benchmark/dataset.json`，5 张开发查询、10 张测试查询。划分按采集顺序固定，不使用类别当作相关性真值；同类不同外形也可能不相关。

清单包含逐图 SHA-256、来源、摄影师、许可、分区和版本哈希。原始来源 ID、文件哈希无交叉，dHash 自动近重复候选为 0，仍需两人独立人工复核。标注页面 `assets/image_search_benchmark/annotation.html` 按 SKU 编码展示图库，不显示模型排序。强相关记 2，弱相关记 1，不相关记 0；分歧由第三人裁定并写明理由。三份空白模板不是评测结果。

来源审查发现旧目录中 W02、T03 的照片页链接误用了 W01 的页面，已按原始下载编号校正两条链接，并保留修正前清单与本地数据库备份。平台返回访问验证，来源页的最终在线复核仍由人工完成，标注页面已提示。当前清单因此有新的元数据版本，图片、SHA-256 和 SKU 均不变；下述初次计时仍对应归档的初次清单版本，正式标注与评测使用当前版本重新执行。

Recall@5 对每个有强相关项的查询计算“命中的强相关 SKU 数 / 所有强相关 SKU 数”，再求均值。没有强相关项的查询不进入 Recall 均值。Precision@5 对每个未排除查询使用固定分母 5，包括无匹配查询；返回不足 5 项也不缩小分母。排除查询与无匹配查询分别记录。

默认正式评测必须提供两份已完成标注；有分歧还需提供独立裁定。空白、同一标注人、版本不符、SKU 不完整或未裁定时停止，不生成指标。`--predict-only` 明确输出 `awaiting_human_annotations` 和空相关性指标，允许保存原始排序与耗时供后续复现。

## 已执行实验及其限制

2026-10-29 已在本机 CPU、Python 3.13.5、PyTorch 2.9.1+cpu、TorchVision 0.24.1+cpu 上运行两种方法，精确版本和原始 Top-5 记录保存在 `.qa/m4-benchmark/test-comparison.json`。10 张固定测试查询的初次离线热态 P95 为主方法 103.333 ms、基线 27.101 ms；口径包含读取/解码、特征和矩阵排序，不包含 HTTP、数据库和索引加载。该初次记录与回归进程并行执行，系统负载未控制，不能据此宣称正式性能验收通过。

随后在独立 20 张图库的 FastAPI TestClient 上执行真实 multipart 请求，包含业务过滤、响应序列化和日志提交。并发为 1，每种方法一次首次请求和 10 次热态请求，原始记录在 `.qa/m4-benchmark/api-latency.json`：主方法首次请求约 11956 ms，热态 P95 为 207.499 ms；颜色基线首次约 98.051 ms，热态 P95 为 124.670 ms。该口径不包含 TCP/TLS 与外部网络，操作系统其他负载未控制，样本量较小，不能等同于生产环境端到端 P95。

首次视觉请求的主要开销是模型与运行库加载。正常 local/production 启动在已有模型与索引时会预加载；`IMAGE_SEARCH_PRELOAD=0` 可关闭。预加载会增加启动等待时间，缺少模型或预加载失败时保留其他商城功能。测试环境关闭自动预加载，以便分别测量冷、热请求。

补充验证在真实 local 模式服务启动后确认 `model_preloaded=true`，20 张索引就绪；首个真实本地 HTTP 图搜请求约 678.867 ms，返回 5 个候选。该单次功能验证记录在 `.qa/m4-benchmark/startup-preload.json`，不是 P95 统计。

当前正式 Recall@5、Precision@5 均为“待人工标注后计算”，未判断 ≥0.75 和 ≥0.60 的建议目标是否满足。没有拿同源图片、变换图或粗分类准确率代替独立查询评测。

## 观察到的失败类型

开发图 Q-27781350 的初次无灯型过滤结果中出现壁灯和落地灯；它们可能具有相似灯罩或背景，但安装类型与参考台灯不同。这说明通用视觉嵌入会受整体场景和相近局部结构影响。用户选择台灯分类后只返回台灯，但离线两方法比较仍统一使用完整图库，不借用人工查询类别提前过滤。

其他待复核情况包括目标灯具过小、中心裁剪截掉主体、暗光、遮挡、多灯场景，以及颜色基线把相近房间背景当作相关。后续改进应只在开发集上确定，再冻结方案并在测试集评测；可考虑灯具主体裁剪、领域样本和经标注校准的无匹配阈值。当前没有宣称这些改进已经实现或提升指标。

## 启动和复现

在后端先安装 `requirements-image-search.txt`；开发/测试还需 `requirements-dev.txt`。安装 CPU PyTorch 的具体索引按官方平台说明配置。然后在项目根目录准备已经取得的官方权重：

```powershell
python tools/prepare_image_search_weights.py
# 缓存不在默认位置时：
python tools/prepare_image_search_weights.py --source 本地路径/resnet18-f37072fd.pth
python tools/upgrade_local_m4.py
```

全新数据库直接运行 Alembic 迁移；已有默认演示库可使用备份升级工具。进入 `apps/api` 后执行 `python -m app.build_image_index`，或登录管理端点“建立或更新索引”。三端启动方式见 README。

```powershell
python tools/prepare_image_benchmark.py
python tools/evaluate_image_search.py --predict-only --split test
python tools/evaluate_image_search.py --review-a 标注A.json --review-b 标注B.json --adjudication 裁定.json --split test
```

`tools/benchmark_image_api.py` 用独立 `.qa/m4-browser` 夹具计时，不应对真实用户数据运行；正式部署测量应另设确认过的硬件、图库、网络和负载条件。微信组件的公共源码在 `apps/shared/ImageSearchPanel.vue`，各端 dev/build 前自动同步到应用 src 内，以兼容微信编译器。
