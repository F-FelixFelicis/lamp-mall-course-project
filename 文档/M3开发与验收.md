# M3 模拟订单履约开发与验收

本阶段将商品报价接入模拟订单履约，支持顾客下单、商家处理、顾客收货与评价。页面明确标记模拟交易，不收取款项；不存在支付、退款或真实物流接口。

## 三端演示顺序

1. 先运行数据库迁移并启动后端、顾客端、商家端和管理端。已有默认本地 SQLite 数据库可在项目根目录运行 `python tools/upgrade_local_m3.py`，自动创建并验证升级前备份；全新数据库直接运行 `alembic upgrade head`。
2. 顾客登录，从商品详情选择规格和商家报价，点击“模拟下单”。确认数量与报价，添加或选择本人测试收货地址，提交后状态为“待确认”。
3. 商家从工作台点击“订单管理”，仅看到本店订单。可确认接单进入“待发货”，或填写原因拒绝，拒绝后订单为“已取消”。
4. 商家填写模拟承运方、运单号并上传本人发货凭证，确认后进入“已发货”。凭证不能通过匿名链接公开读取。
5. 顾客在“我的订单”查看报价、规格和地址快照、状态轨迹与发货信息；确认收货后进入“已完成”，可对订单项提交一次 1–5 星文字评价。
6. 管理端新增“订单查询”，可查看全部订单详情与履约轨迹，不代替商家接单或顾客收货。

## 订单、库存和快照约定

- 状态为 `PENDING_CONFIRM → TO_SHIP → SHIPPED → COMPLETED`。商家仅能拒绝待确认订单；顾客可取消待确认或待发货订单，均转 `CANCELLED` 并记录原因。已发货后普通取消被拒绝。
- 提交时校验当前商家资质、商品上架与分类状态、SKU、有效报价及库存。价格与顾客确认值不一致时返回 `PRICE_CHANGED`，要求重新确认。
- 创建订单时扣减报价的可用库存，取消/拒绝时释放一次。状态、版本、库存、事件和操作日志同事务提交，失败整体回滚。
- `idempotency_key` 按顾客隔离且唯一。相同键与相同请求重试返回同一订单；键被用于不同请求返回冲突。订单状态变更使用版本号，过期操作不会再次修改库存。
- 每单仅含同一商家的商品，接口支持最多 20 项，单项数量 1–999。不同商家的商品须分别下单。顾客页面当前提供单规格直接下单，尚无购物车。
- 订单保存成交价、数量、单位、商品名、规格、商家名、商品图片引用和收货地址快照。地址修改或删除不改变历史订单；商品名或后续报价变化也不重算历史金额。
- 当前库存依附报价记录。有待确认/待发货订单时，禁止审核替换该商家该 SKU 的报价，并禁止修改该 SKU 规格，返回 `UNSHIPPED_ORDERS`。待履约或取消后再调整，避免库存被新报价覆盖。未来独立库存台账可解除此限制。
- 商品下架后，订单归属顾客、归属商家和管理员仍可读取关联快照图片；发货凭证仅上传者、订单参与方和管理员可读。无关用户或跨商家访问被拒绝。
- 只有对应顾客的已完成订单项可评价一次；商品公开评价不暴露顾客 ID、电话、地址或订单号。
- API 与数据库时间为 UTC，新增订单页面按北京时间显示。

## 数据库与接口

M3 迁移 `6acd820e89f8` 新增六张表：`customer_addresses`、`orders`、`order_items`、`order_events`、`shipment_records`、`reviews`。连同 M1/M2 共 20 张业务表。迁移不删除既有账号、商品、报价和审核记录。

主要接口如下，参数与响应以 `api/openapi-m3.json` 和运行时 `/api/openapi.json` 为准。

| 接口 | 用途 |
| --- | --- |
| `GET/POST /addresses`、`PUT/DELETE /addresses/{id}` | 本人地址列表、新增、修改、软删除 |
| `POST /orders`、`GET /orders` | 创建订单、本人订单分页 |
| `GET /merchant/orders`、`GET /admin/orders` | 商家本店与管理员订单分页 |
| `GET /orders/{id}` | 有权参与方读取详情、快照、轨迹 |
| `POST /orders/{id}/actions` | 确认、拒绝、取消、发货、收货 |
| `POST /order-items/{id}/review` | 已完成订单项评价 |
| `GET /products/{id}/reviews` | 可售商品的公开评价分页 |
| `POST /files`，用途 `SHIPMENT` | 上传发货凭证，沿用文件内容校验与私有授权 |
